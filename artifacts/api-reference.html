REST API Reference

Base URL: http://localhost:8888 — keep src/api/config.ts in sync if this changes.

No auth yet

{userId} and other path parameters are currently plain numeric IDs, with no auth token required. See the PRD's non-functional notes for this gap.

CartController — /api/users/{userId}/cart

MethodPathPurpose
GET/cartRaw cart rows (frontend consolidates via cartLogic.consolidateCart)
PATCH/cart/adjust+1/-1 tap. Body: { itemId, storeId, delta }
PATCH/cart/items/{cartItemId}/pantry-overrideSet "already have" quantity. Body: { overridePantryQty, overrideReason }
PATCH/cart/items/{cartItemId}/checkout-statusToggle Away Mode checkbox. Body: { checked }
POST/cart/master-resetClears every checkbox for the user, no body
POST/cart/complete-checkoutZeroes quantity + unchecks every checked row for one store. Body: { storeId }

RecipeController — /api/users/{userId}/recipes

MethodPathPurpose
GET/recipesAll saved recipes, base (×1) quantities
POST/recipesCreate a recipe. Body: { name, ingredients: [{ itemId, baseQuantity, unit, targetStoreId? }] } ○ not yet called by the frontend UI

PurchaseHistoryController — /api/users/{userId}/purchases

MethodPathPurpose
GET/purchasesReceipt-level history, feeds every Insights chart
POST/purchasesArchive one receipt. Body: { storeId, totalReceiptSpent, purchaseDate?, items: [{ itemId, itemName, category, quantity, pricePerUnit }] }

StorePriceController — /api/stores/{storeId}/prices

MethodPathPurpose
GET/pricesAll known item prices at this store
PUT/pricesBulk upsert. Body: { updates: [{ itemId, priceAmount }] } — called by the receipt scanner's confirm step

UserController — /api/users/{userId}

MethodPathPurpose
GET(root)User profile, including persisted currentMode
PATCH/modeUpdate Home/Away mode. Body: { mode: "HOME" | "AWAY" }

Not yet implemented

○ Planned POST /api/receipts/scan — the OCR + LLM receipt-matching endpoint from Feature 4 does not exist on the backend yet. The frontend's ReceiptScannerScreen currently calls a local mock function that returns a hardcoded result after a simulated delay. Everything downstream of the scan (the review UI, manual match correction, and the "Confirm" action's calls to PUT /prices and POST /purchases) is fully real.
